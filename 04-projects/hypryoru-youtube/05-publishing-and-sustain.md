# 05 Publishing and Sustain

## Packaging
- Title: [Result + time/scope]. Eg: `Hyprland Waybar Setup in 12 Minutes (Lua + Matugen)`. Include the topic keyword (`Hyprland`, `Arch`, `Neovim`, or the project name). Question vs list — test both, keep winner.
- Description template: 2-line hook, timestamps, repo/commit link (dotfiles or project), install/run command, hardware (eDP-1 note), playlist link.
- Tags: hyprland, arch linux, hyprland rice, waybar, matugen, linux customization + 1 topic tag (neovim, tmux, build in public, arch maintenance…) + 1 module/project tag.
- Playlist per series/pillar + autoplay on (Build Log / Module Guide / Tool Guide / Build in Public / Fix & Maintain). End screen: 1 spoken recommendation only, not 4 cards.
- Thumbnail: rice + 3 words. A/B via CTR after 48h.

## Cadence
1/week min, 2/week max. Batch: record 2 one day, edit another day. Never record+edit same day.
Bank rule: keep 1 finished video unreleased. Covers illness/holiday.

## Idea flywheel
`00-inbox/youtube-inbox.md` — 1 line per dotfiles edit or Linux question you answer for yourself.
Weekly: promote top 3 to backlog. Never start week blank.
Comment mining: every "how?" comment = next Build Log. Reply with timestamp + promise video.

## Metrics (track only these)
- CTR (target >4% after 1k impressions)
- 30-sec retention (target >65%)
- Avg view duration + comments asking for dotfiles
Kill rule: 5 videos in a format <30% retention = drop format, double top 2.

## Anti-burnout
- Same intro/outro file. Same mic chain. Same OBS scenes. No per-video setup.
- Evergreen > news. Module Guides rank for years, news dies in days.
- Break-glass formats when tired: Fix in VM (no script), Q&A from comments, Short from winner.
- Quarterly: prune backlog, archive dead ideas, update top 2 descriptions with new commit.
